# Daily Floor 引き継ぎ書

## 目的

Daily Floor は、生活・作業・勉強・連絡・手続きなどに「少しだけ触れる」ことを支えるローカルファーストPWAです。

このアプリは、先延ばしを怠惰や意志の弱さとして扱わず、次のような流れとして扱います。

1. タスクを見る
2. 不安、眠気、面倒さ、恥ずかしさ、身体の重さなどが出る
3. 避ける
4. 自己批判が出る
5. さらに避けやすくなる

Daily Floor の目的は、この流れを責めずに止めることです。通常量をこなすことより、接触を切らないこと、今日の状態を記録すること、休む判断を失敗扱いしないことを優先します。

## 何のために作ったか

- タスク開始前に固まる状態を減らす
- 0秒の接触でも記録できるようにする
- 「できなかった」を失敗ではなく事実ログにする
- 睡眠不足や低エネルギー時に目標を下げる
- 医師、カウンセラー、仕事関係者へ共有できる事実メモを作る
- すべてのデータをブラウザ内に保存し、外部へ送らない

## 作り方の基本方針

### Local-first

データは IndexedDB に保存します。外部DB、外部ログ、外部分析、バックエンドは使いません。

理由:

- 生活・感情・睡眠・回避ログは非常にセンシティブ
- ユーザーが明示的にエクスポートしない限り外へ出さない設計にしたい
- GitHub Pages だけで配布できるようにしたい

### GitHub Pages-only PWA

構成:

- React
- TypeScript
- Vite
- vite-plugin-pwa
- Dexie / IndexedDB
- Web Worker for reports
- Hash routing

GitHub Pages のサブパス配信に合わせ、Vite の `base` は `/daily_floor/` を既定にしています。

### UI言語

UIは日本語です。特に、ユーザーが固まりやすい画面では専門用語を避け、ボタンを押すと何が起きるかを明記します。

例:

- `開始` ではなく `細かく開始`
- `接触できた` ではなく `接触を記録`
- `休養ログ` ではなく `休養を記録`

## 重要なUX原則

### 入口は1つにしない

初期実装では「チェックイン」から始めるように見えましたが、ユーザーは起床時ではない場合や入力する気力がない場合にフリーズします。

現在の入口:

- 状態メモ
- 細かく開始
- 接触を記録
- 休養を記録
- タスク追加
- 夜レビュー

どれから入ってもよい設計にしています。

### 押した後に何が起きたかを必ず見せる

ユーザーはボタンを押した後に画面が上へ戻るだけだと、保存されたのか、失敗したのか、次に何をすればよいのか分からなくなります。

現在は、即時記録ボタンを押すとページをリロードせず、同じ画面に保存結果を表示します。

例:

- 接触を記録 → 「作業が0秒でも、今日の接触ゴールは完了」
- 休養を記録 → 「失敗ではなく、今日の状態を残すゴール」

### ゴールを明確にする

Daily Floor のゴールは「通常量を完了する」だけではありません。

以下のどれかを記録できればゴールです。

- タスクを少し進めた
- 5分だけ触れた
- ページやメモを開いただけ
- 今日は無理だと休養ログを残した

### `floor` と書く

UIでは「床」ではなく `floor` と書きます。

理由:

- 「床」は比喩として伝わりにくい
- `floor` をアプリ内の固有語として扱う方が混乱が少ない
- ただし、初見ユーザーにはガイドで意味を説明する

## 医療安全

このアプリは医療アプリではありません。

禁止:

- 診断
- 服薬助言
- 治療判断
- 「躁」「うつ」などの断定
- ユーザー状態の医学的推定

許可:

- 事実ログ
- 共有候補
- 注意して見たい変化
- Markdownレポート

レポートも「これは何を示すか」ではなく、「何が記録されたか」を出します。

## 現在の主要画面

### Today

その日に何をするかを見る画面です。

役割:

- 今日の状態を表示
- 今日のfloorを表示
- 即時記録ボタンを提供
- ガイドへの入口にする

重要:

- ボタンは押した結果が分かるようにする
- 画面遷移するボタンと保存するボタンを混ぜない
- 保存した場合は必ず成功メッセージを出す

### 状態メモ

元は朝チェックインでしたが、起床時限定に見えてしまうため、現在は「状態メモ」に変更しています。

役割:

- 今の眠気
- 気分の重さ
- 不安
- 身体の重さ
- 任意の睡眠情報

睡眠時間や起床時刻は任意です。空欄があっても保存できます。

### カスケード

タスクを小さくしていく画面です。

流れ:

1. 感情ラベル
2. if-then
3. 報酬
4. 5分タイマー
5. 開くだけ
6. 休養ログ

この画面では、「記録して終わるボタン」と「次へ進むボタン」の違いを明示します。

### ガイド

ユーザーが迷ったときに見る画面です。

含めるべき内容:

- 入口は1つではない
- 状況別にどこを押すか
- 何をしたらゴールか
- ボタンを押すと何が起きるか
- 用語の意味

## 日記PWAへ引き継ぐべき考え方

ユーザーは今後、時系列で上から下へ確認できる日記PWAを作りたいと考えています。

Daily Floor から引き継げる考え方は以下です。

### 1. 入口を複数にする

日記アプリでも「新規日記を書く」だけを入口にすると、書く気力がない時に固まります。

入口例:

- 1行だけ書く
- 今の気分だけ選ぶ
- 写真やURLだけ残す
- 今日あったことを箇条書きで1つ
- 後で書くための空メモを作る
- 何も書けなかったことを記録する

### 2. タイムラインは「編集対象」ではなく「安心して眺める場所」

時系列画面は、ユーザーが自分の生活を責めずに見返す場所にします。

避けること:

- 空白日を強調する
- 継続日数を失敗として見せる
- 赤い警告で埋める
- 感情を診断する

使う言葉:

- 記録あり
- 共有候補
- 後で追記
- 今日は短め
- 事実メモ

### 3. 投稿後のフィードバックを出す

日記でも、保存後にただタイムラインへ戻るだけだと不安になります。

保存後の例:

- 「1行メモを保存しました」
- 「今日の記録として残しました」
- 「あとで追記できます」
- 「空メモを作りました」

### 4. 日記のゴールを広くする

日記のゴールは「長文を書く」ではありません。

ゴール例:

- 1語だけ書いた
- 気分だけ選んだ
- 写真だけ残した
- 何も書けなかった理由を残した
- 後で書く枠だけ作った

### 5. 日記PWAのデータモデル案

```ts
type DiaryEntry = {
  id: string;
  date: string;
  createdAt: string;
  updatedAt: string;
  kind: "text" | "mood" | "photo" | "url" | "empty" | "later";
  title?: string;
  body?: string;
  mood?: "good" | "flat" | "heavy" | "anxious" | "tired" | "unknown";
  tags: string[];
  source?: "manual" | "share";
  shareCandidate: boolean;
};
```

### 6. 日記PWAの画面案

- Today
  - 今すぐ1行
  - 気分だけ
  - 後で書く
  - 空白を記録
- Timeline
  - 上から下へ時系列
  - 日付ごとにまとまり
  - 短い記録も同じ重さで表示
- Entry
  - 追記・編集
  - タグ
  - 共有候補
- Reports
  - 記録数
  - 多かった気分
  - 睡眠や活動との関係は事実だけ
- Backup
  - JSON
  - Markdown
  - CSV

## 次の開発者への注意

- ユーザーは「ボタンを押した後に何が起きたか」が不明だと止まりやすい
- 画面遷移と保存処理を同じ見た目のボタンにしない
- ゴールを1つに固定しない
- 書けない日、できない日、休む日を失敗として扱わない
- 医療的な推定をしない
- PWA通知は信頼できる前提にしない
- データは常にエクスポート可能にする

## 一文でまとめる

Daily Floor は、ユーザーが「何もできなかった」と感じる日に、接触・floor・休養ログのどれかを安全に記録し、自分を責めずに次の日へつなげるためのローカルファーストPWAです。
